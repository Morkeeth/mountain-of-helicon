## Findings (the substance)

### 1. UNMEASURABLE is the wedge

- Source: published blog threshold — "memory accuracy drops past 10K **interactions**"
- Five defensible readings on one store: 28 → 15,001
- Verdict: **UNMEASURABLE** (not INSIDE, not CLEAR — **honest**)
- **Claim:** A number the field cites but cannot operationalize is not a threshold — it's marketing with SQL-shaped clothes

### 2. Wrong-object ratios are the hook

- Stored >> retrieved; reviews >> human reviews
- Any pitch that sells the store as "memory the agent reads from" describes the **wrong object**
- **Claim:** Most agent-memory products are judged, not read — and nobody prints that ratio

### 3. Witness over assertion (architecture)

| Layer | Role |
|---|---|
| `helicon measurement-bench` | Deterministic probes — source of truth |
| `POST /run` agent | Subprocess only — **0 probe reimplementations** in cloud experiment |
| Gemini (later) | Narrates frozen JSON — **never picks an interaction count** |

Cloud agent experiment (20 Aug): explicit constraints → agent did not reimplement science. Hosted cloud arm pending API key + git push.

### 4. What generic hackathon ideas fail

Killed (convergence): OpsPilot, DemandOps, eval-scientist — **first-in-mind from the brief**.  
Kept: Oscar's lived 536× problem + personal measurement series — **un-derivable without his store**.

## Q&A prep

**"Isn't this too nerdy?"**  
Lead with store truth (535× written vs read) — everyone gets that. UNMEASURABLE is the punchline for technical judges.

**"How is this different from eval tools?"**  
Evals score text vs text. We score **published claims vs your live store** with repro SQL.

**"One product or three?"**  
One product: **instruments (science) + logbook (measure) + wrong-object lens (store truth)**. Same witness law.

**"Cloud?"**  
Product is CLI-first; GCP is thin async wrapper for hackathon proof — not a second product.
