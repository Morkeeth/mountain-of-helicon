# Mount Helicon V2 — night run 2026-07-21

## What this is
The V2 felt use case, built as one working vertical slice: **the Cockpit** — the opening surface that reviews what your agents actually produced across terminals, catches a wrong claim, lets you correct it once, and proves the next run receives the correction. Built in an isolated worktree off frozen `main`. Not a mockup — the loop closes on your real local terminal state.

The hero sentence, made materially real:
> Five agents ran. I can see exactly what each produced, catch the wrong claim before it spreads, correct it once, and know the next run received the correction.

## Product path built
One calm path, ORIENT → INSPECT → COMPARE → RULE → APPLY → PROVE → RETURN CALMER:
1. **ORIENT** — `/api/cockpit` runs the wired `review_terminals.verify()` engine over a SAFE allowlist of your real `~/CODE` repos; every terminal shows objective, actual git change, produced artifacts, per-claim verdict, and a needs-you flag. Needs-you first.
2. **INSPECT** — click a terminal → its actual artifact renders **natively** (a new dependency-free, injection-safe Markdown + unified-diff renderer). The artifact is the visual center, not a description of it.
3. **COMPARE** — each claim sits beside grounded reality (git upstream/merge state, route-file grep, re-run tests). "Unverified" never silently becomes fact.
4. **RULE** — Keep / Revise / Reject. **Revise captures the correction verbatim** (V1 discarded it) into a governed correction cube.
5. **APPLY + receipt + undo** — the ruling resolves the finding, writes the correction, and offers a working Undo.
6. **PROVE CONTINUITY** — "Send to agent context" compiles the correction into the files the next agent auto-loads (in a **sandbox**), and proves the correction is present. Honest about include-vs-obey.
7. **RETURN CALMER** — a ruled claim leaves the queue (never-twice).
