## LANE 1 — THE SWEEP (do this one first)

**Objective.** Point the instrument outward and produce the one number that does not
exist yet: across every repo under `~/CODE`, how many loaded agent-context claims does

**Why it beats the alternatives.** Everything shipped this week measures one repo at a
time, on demand. Nobody has ever run it across the whole tree. This is the first output
of this project that is a *finding about the world* rather than a fact about Helicon,
and it is the demo asset — a ranked board of real repos with real contradicted lines and
real probe stdout.

**Build.**

  concurrently, with a per-repo timeout. Reuse `doorway.verdict` — it already caches on a
  fingerprint, so the second sweep is near-free. Do NOT write a second probe path.
- Output: repos ranked by contradicted-claim count, each line with `file:line`, the
  claim, the probe command, and its real stdout.
- `--json` for the machine; a one-screen text render for a human.
- Persist each sweep so the NEXT sweep can print the delta (what got fixed, what rotted).

**Done when.** A single command prints the ranked board across all ~37 repos, and the
PR body contains its real stdout plus the headline number ("N repos carry M claims their
own code disproves"). A repo that cannot be probed reads UNVERIFIABLE with the reason.

**Files.** `helicon/doorway.py`, `helicon/cli.py`, `tests/test_doorway_sweep.py`.

**Watch for.** Today's dogfooding found the probe's two false-positive classes — a

- `helicon doctor` gains a doorway section: is the hook installed, does the wrapper

**Done when.** On a clean checkout with no prior config, this sequence works and its real

`pip install -e . && helicon init && helicon doorway install && cd <a repo> && <prompt blocked>`

**Files.** `helicon/doorway.py`, `helicon/cli.py`, `pyproject.toml`,

## LANE 3 — OBEYED

**Objective.** Close the last honesty gap in the loop. Delivery is now *proven*
(`helicon receipt` reads the harness's own transcript). Whether the agent **obeyed** the
injected context is still unproven, and the run card says so in plain text.

**Why.** This is the difference between "we injected context" and "context changed the
run". Without it, every claim about Helicon improving a run is an assertion.

**Build.**
- For a closed run whose packet was RECEIVED, check the session's actual output against
  the packet's claims: did the run cite, contradict, or ignore each delivered item?
- Verdicts per item: `OBEYED` / `CONTRADICTED` / `UNUSED` / `UNVERIFIABLE`. Roll up to
  the run card, replacing the literal `obeyed: unproven`.
- Deterministic evidence first (did the artifact touch the files the packet named; does
  the output contradict a delivered ruling — `helicon guard` already does this shape).
  An LLM judge may only *rank*, never *establish*, and must be labelled self-graded.

**Done when.** A real run's card reads `obeyed: N/9 items` with per-item evidence, or
says UNVERIFIABLE and why. Proven on the run closed today (`tr_4cba36cdcdf8`, packet
`0ee72b9a7e87c953`, RECEIVED at transcript line 9).
