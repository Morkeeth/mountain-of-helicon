## LANE 1 — THE STATE OF AGENT CONTEXT (the swing — do this one)

**Objective.** Answer, with executed probes and pasted stdout, a question nobody has
answered about the whole ecosystem:

> **Of the public repos that ship a `CLAUDE.md` / `AGENTS.md` / `.cursorrules`, what
> fraction contain claims their own code disproves?**

Not Oscar's 37 repos. The **public** ones — the top N repos on GitHub carrying an
agent-rules file. Same engine, ~100x the reach, and the output is a finding about the
industry rather than a fact about one laptop.

**Why this and not the local sweep.** A sweep of `~/CODE` is a report Oscar reads. This
is a **launch**: it has the three properties internal work never has — a date (this
weekend), an external judge (whoever reads it), and a demo artifact (the report, and the
one-command gate that produced it). It also inverts the sales pitch: instead of "here is
my memory tool", it is "here is a measured, reproducible failure mode in how everyone
runs coding agents, and here is the check that catches it."

**Build.**
1. **The engine.** `helicon sweep <repos...>` / `--from <file>`: clone shallow into a temp
   dir, run the existing `doorway.verdict` per repo, concurrent, per-repo timeout,
   nothing written back to the clone. Reuse `doorway.verdict` and `probes.probe_docs`
   as-is — **do not write a second probe path**.
2. **The corpus.** Discover public repos with an agent-rules file at root via the GitHub
   code-search API. Record the exact query and date; the corpus must be reproducible by
   a stranger. Target ≥200 repos; report the real N you reached, never a round number.
3. **The report.** `docs/agent-context-report-2026-08.md` — headline rate, distribution
   by contradiction count, the breakdown by claim kind (a retired capability still
   advertised / a named path that is gone / a quoted command whose output disagrees),
   and for each finding the probe command and its real stdout. Plus the honest
   denominators: how many repos were UNVERIFIABLE and why.
4. **The install path.** One command at the end of the report that lets a reader run the
   same check on their own repo. If Lane 2 has not landed, this is where it becomes
   urgent — a report nobody can act on is a blog post, not a product.

**Done when.** The report exists with a real N, a real rate, and reproducible per-finding
evidence; and a stranger can re-run the sweep from the documented corpus query.

**Files.** `helicon/sweep.py` (new), `helicon/cli.py`, `docs/agent-context-report-2026-08.md`,
`tests/test_sweep.py`.

**Accuracy is the whole product here — read this twice.** Today's dogfooding found two
false-positive classes in the probe: a committed fixture corpus read as running code, and
"git tracks no such file" read as disproof (`tests/test_probes_false_positives.py`).
Those alone accounted for **11 of 14** contradictions on two local repos. At 200 repos
this is the only thing that matters:

- **Hand-verify a random sample of ≥30 findings** before any number is published. Report
  the sampled precision as a real fraction, in the report, next to the headline.
- Any new false-positive class: fix the class, add its regression test, re-run. Do not
  ship a number with a known-bad class in it.
- Publish **aggregate rates by name**; for individual repos, publish the finding only
  where the evidence is unambiguous, frame it as "the doc and the code disagree" (never
  "this project is wrong"), and offer maintainers the per-repo detail. We are measuring a
  systemic failure mode, not scoring strangers.
- A rate that turns out to be *low* is still the finding. Publish it either way.

**Anti-goal.** Do not build a leaderboard, a submission form, or a hosted service this
run. One report, reproducible, with the check that produced it.

## LANE 2 — THE STRANGER

**Objective.** Make the doorway installable by someone who is not Oscar, on a machine
that is not this one, in one command.

**Why.** The gate currently depends on a hand-written `config.json` with an absolute
`db_path`, a wrapper script with a hardcoded-by-inference repo root, and a `helicon`
console script that **raises `ModuleNotFoundError` from any directory outside a
checkout**. That last one is the tell: a hook wired to the PATH binary would have failed
on every prompt, silently, forever. Nobody else can run this today.

**Build.**
- `helicon doorway install` — writes the `UserPromptSubmit` block into
  `~/.claude/settings.json` **only with explicit confirmation**, shows the diff first,
  never clobbers existing hooks, and is idempotent. `--uninstall` removes exactly what it
  added. `--print` keeps the current dry behaviour.
- Fix the packaging so `helicon` works from any cwd after `pip install -e .`.
- `helicon doctor` gains a doorway section: is the hook installed, does the wrapper
  resolve, does the config exist, when did the gate last fire.

**Done when.** On a clean checkout with no prior config, this sequence works and its real
stdout is in the PR:
`pip install -e . && helicon init && helicon doorway install && cd <a repo> && <prompt blocked>`

**Files.** `helicon/doorway.py`, `helicon/cli.py`, `pyproject.toml`,
`scripts/claude-doorway-hook.sh`, `tests/test_doorway_install.py`.

**Constraint.** Writing to `~/.claude/settings.json` is the single most dangerous thing
in this repo. Back it up, diff it, confirm it, and make uninstall exact. A tool that
corrupts a user's settings has no second chance.

## LANE 3 — OBEYED

**Objective.** Close the last honesty gap in the loop. Delivery is now *proven*
(`helicon receipt` reads the harness's own transcript). Whether the agent **obeyed** the
injected context is still unproven, and the run card says so in plain text.

**Why.** This is the difference between "we injected context" and "context changed the
run". Without it, every claim about Helicon improving a run is an assertion.

**Build.**
- For a closed run whose packet was RECEIVED, check the session's actual output against
  the packet's claims: did the run cite, contradict, or ignore each delivered item?
- Verdicts per item: `OBEYED` / `CONTRADICTED` / `UNUSED` / `UNVERIFIABLE`. Roll up to
  the run card, replacing the literal `obeyed: unproven`.
- Deterministic evidence first (did the artifact touch the files the packet named; does
  the output contradict a delivered ruling — `helicon guard` already does this shape).
  An LLM judge may only *rank*, never *establish*, and must be labelled self-graded.

**Done when.** A real run's card reads `obeyed: N/9 items` with per-item evidence, or
says UNVERIFIABLE and why. Proven on the run closed today (`tr_4cba36cdcdf8`, packet
`0ee72b9a7e87c953`, RECEIVED at transcript line 9).

**Files.** `helicon/attribution.py`, `helicon/taskrun.py`, `tests/test_obeyed.py`.
